- 화면(2026-10-12 개편): 상단 앱 바(브랜드·탭 메뉴·테마 버튼·기록 관리) + 휴대폰 하단 탭. 따뜻한 종이색 라이트/숯색 다크 테마, Pretendard 웹폰트(CDN, 실패 시 시스템 글꼴). 홈은 첫 방문 소개 또는 '이어서 하면 좋은 것'(오답 복습·약한 파트·개념 노트) + 통계 묶음 + 01 과목/02 파트(장별 두 단)/03 학습 설정. 텍스트 보기는 ①~④를 블록으로 나눠 표시(문구 불변), 표·도표가 없는 문항은 텍스트 보기가 기본. 결과 화면은 문항 첫 문장 표시, ←/→ 키 이동, 휴대폰에서 정답 확인/다음 버튼 하단 고정
- 테마: 상단 버튼으로 자동/라이트/다크 순환, 설정 창에서도 선택. 다크에서는 원본 스캔을 반전(설정에서 끌 수 있음). 저장 키는 `chagok.theme`, `chagok.img`로 학습 기록과 별개이며 `index.html` 머리의 인라인 스크립트가 첫 렌더 전에 적용
- 스타일은 `assets/app.css`의 CSS 변수(`:root`, 다크는 `prefers-color-scheme` + `:root[data-theme=dark]` 두 곳에 같은 값)로 관리합니다. 휴대폰에서 `.appbar`에 `backdrop-filter`를 다시 넣으면 하단 탭(`nav`, position:fixed)이 상단 바 기준으로 붙어 버리니 넣지 마세요
- 개발용 `review.html`: 유사 문제 나란히 비교, 분류 검토, 원문 보류 문항 확인

일반 앱에서 제외한 원문 보류 1문항은 데이터와 검토 화면에 남겨 두었습니다. 최신 법령 검증과 전문가의 전 문항 분류 검수를 완료한 상태는 아닙니다. 해설은 30문항을 작성했으며, 나머지 문항과 계정·자동 동기화·PWA 서비스 워커는 아직 없습니다.

## 데이터 구조와 중요한 규칙

1. `data/questions.json`은 4,560개 원본 출제 기록입니다. `id` 형식은 `연도-월-전체문항번호`입니다. 예: `2026-07-026`.
2. `entry_id`가 `data/entries.json`의 대표 항목을 가리킵니다. 각 항목의 `occurrence_ids`에 같은 문제의 모든 출제 이력을 보존합니다.
3. `family_id` 및 `data/families.json`은 문구가 같고 수치만 다른 변형을 연결합니다. 기본 화면은 `representative_entry_id`를 쓰되 `study_eligible: false`를 제외합니다.
4. `answers`는 숫자 배열입니다. 선택지의 순서가 달라도 문항을 합칠 수 있지만, 대표 원문의 보기와 그 원문의 답안을 한 세트로 사용해야 합니다. 서로 다른 회차의 보기와 답안 번호를 섞지 마세요.
5. 수치·단위·부정 표현·도표·정답 내용이 다른 문제를 함부로 합치지 않습니다. 유사도는 후보 검색용입니다. `data/review-candidates.json`의 후보는 아직 따로 유지 중입니다.
6. `classification`에 주 파트 하나, 보조 태그, 관련 파트 후보, 신뢰 수준과 검토 표시가 있습니다. 신뢰 수준은 규칙 점수이며 검증된 정확도 확률이 아닙니다. 중복 원본에는 같은 대표 분류를 상속합니다.
7. `data/part-overrides.json`은 내용을 확인한 수동 분류와 이유입니다. 자동 분류 변경은 `scripts/classify_parts.py`의 규칙·우선순위에 반영합니다.
8. `tax_law_year`는 원문에 명시된 적용 세법 연도입니다. 시험 연도로 추정하지 않습니다.
9. 추출 텍스트는 표·수식의 정확한 배치를 보장하지 않습니다. 표시 원본은 `image`, `source_pdf`, `page`, `clip`으로 추적합니다.
10. `data/source-exams.json`의 상대 경로와 `sources/`로 PDF부터 재생성할 수 있습니다. `data/source-manifest.json`은 PDF 해시 기록입니다.

## 개인 학습 기록 호환성

저장 키는 `chagok.study.v1`, 저장 형식 `version: 1`입니다. 주요 필드는 `results`, `bookmarks`, `sessions`, `active`이며 문항 ID를 참조합니다. 사용자의 로컬 기록은 이 저장소나 이 AI 세션에 포함되지 않습니다.

ID 재배정이나 데이터 그룹 변경, 저장 형식 변경 시 기존 기록을 보존할 방법을 고려하세요. 앱의 백업/복원 로직과 검증 함수 `cleanState`, `cleanSession`을 함께 확인하세요. 화면 변경 때문에 기록을 초기화하지 마세요.

- `test_concepts.py`: 개념 노트 구조·파트 연결·출처/상태 일관성·예시 검산·연도별 수치·번들 포함 5개 검사
- `test_app.py`: 실제 UI로 풀이·오답·이어 풀기·복수 정답·백업·모바일·개념 노트 연결 검증

- `test_explanations_app.py`: 30문항 각각 채점 전 숨김·채점 후 해설, 오답 열람, 관련 개념, 기록 유지, 변형 미상속, 준비 중, 모바일, 해설 세트 검증

`reports/`는 검토 문서와 보존한 확인 자료입니다. 새 테스트 이미지·백업 임시 파일은 `_artifacts/`에 생성하며 커밋하지 않습니다. 일부 과거 보고서는 작성 당시의 단계 설명이므로 현재 집계와 이 문서를 함께 확인하세요.

## 배포와 알려진 환경 제약

사용자는 작업 결과를 `main`에 바로 반영하는 방식을 선택했습니다(PR 없이). 작업 브랜치에도 같은 커밋을 올려 두었습니다. 기존 GitHub Pages 설정은 `main`을 반영하는 `pages build and deployment`입니다. 별도 npm 빌드나 새 Actions 워크플로가 필요하지 않습니다. `main` 업데이트 후 해당 커밋의 Pages 실행이 성공했는지 확인합니다.

이 작업 환경에서는 Git push와 github.com의 Actions 페이지 접근은 가능했지만, API와 공개 github.io 주소는 네트워크 허용 목록 때문에 직접 접근이 제한되었습니다. 따라서 "Pages 배포 성공"과 "공개 URL에서 직접 브라우저 검증"은 구분해서 기록했습니다. 로컬 HTTP의 실제 `/jaegyeong/` 경로에서 기능·이미지·PDF 및 기존 사이트 유지 여부는 검사했습니다. 다른 환경에서는 권한·네트워크 조건을 먼저 확인하고 실제 접근 가능한 경로를 사용하세요.

브라우저 테스트 환경 메모: 시스템에 `chromium` 명령이 없으면 Playwright가 내려받은 Chromium 경로를 `PATH`의 `chromium`으로 연결해 `test_app.py`·`test_browser.py`를 실행했습니다. 웹폰트 CDN(jsDelivr)이 막힌 환경에서는 스크린샷이 대체 글꼴로 보이며 이는 정상입니다.
