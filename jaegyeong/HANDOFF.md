- 개발용 `review.html`: 유사 문제 나란히 비교, 분류 검토, 원문 보류 문항 확인

일반 앱에서 제외한 원문 보류 1문항은 데이터와 검토 화면에 남겨 두었습니다. 최신 법령 검증과 전문가의 전 문항 분류 검수를 완료한 상태는 아닙니다. 이전 7차 마무리 당시 등록 해설은 4,145개였으며 그때 추가 확인에서 55개를 순증했습니다. 직전 미해결 231개 전부를 실제 하위 에이전트 6개가 11개 독점 배치로 다시 확인했고 새 공식 원본문 확보 후 62개를 3개 별도 배치로 추가 검토했습니다. 새 후보 57개 전체를 작성자와 다른 에이전트가 독립 검수하여 7차 당시 검토 필요는 176개였습니다. 기존 4,090개 해설 전체 객체·순서·출처, 원문·공식 답안·문항 ID·세법 연도와 학습 기록 형식은 보존했습니다. 개념 노트는 74개·기존 확인 상태를 유지하고 M03의 확인된 원리·예제만 덧붙였습니다. 자세한 결과는 [7차 당시 추가 확인 결과](reports/round7-review.md)를 확인하세요. 이전 6차의 187개 추가·231개 보류와 3차 수치는 역사 기록입니다. 계정·자동 동기화·PWA 서비스 워커는 아직 없습니다.

## 데이터 구조와 중요한 규칙

1. `data/questions.json`은 4,560개 원본 출제 기록입니다. `id` 형식은 `연도-월-전체문항번호`입니다. 예: `2026-07-026`.
2. `entry_id`가 `data/entries.json`의 대표 항목을 가리킵니다. 각 항목의 `occurrence_ids`에 같은 문제의 모든 출제 이력을 보존합니다.
3. `family_id` 및 `data/families.json`은 문구가 같고 수치만 다른 변형을 연결합니다. 기본 화면은 `representative_entry_id`를 쓰되 `study_eligible: false`를 제외합니다.
4. `answers`는 숫자 배열입니다. 선택지의 순서가 달라도 문항을 합칠 수 있지만, 대표 원문의 보기와 그 원문의 답안을 한 세트로 사용해야 합니다. 서로 다른 회차의 보기와 답안 번호를 섞지 마세요.
5. 수치·단위·부정 표현·도표·정답 내용이 다른 문제를 함부로 합치지 않습니다. 유사도는 후보 검색용입니다. `data/review-candidates.json`의 후보는 아직 따로 유지 중입니다.
6. `classification`에 주 파트 하나, 보조 태그, 관련 파트 후보, 신뢰 수준과 검토 표시가 있습니다. 신뢰 수준은 규칙 점수이며 검증된 정확도 확률이 아닙니다. 중복 원본에는 같은 대표 분류를 상속합니다.
7. `data/part-overrides.json`은 내용을 확인한 수동 분류와 이유입니다. 자동 분류 변경은 `scripts/classify_parts.py`의 규칙·우선순위에 반영합니다.
8. `tax_law_year`는 원문에 명시된 적용 세법 연도입니다. 시험 연도로 추정하지 않습니다.
9. 추출 텍스트는 표·수식의 정확한 배치를 보장하지 않습니다. 표시 원본은 `image`, `source_pdf`, `page`, `clip`으로 추적합니다.
10. `data/source-exams.json`의 상대 경로와 `sources/`로 PDF부터 재생성할 수 있습니다. `data/source-manifest.json`은 PDF 해시 기록입니다.

## 실행·검증·패키징

설치 및 명령은 [README.md](README.md)에 있습니다. 모든 Python 스크립트는 자신의 위치에서 앱 루트를 계산하므로 저장소를 다른 디렉터리에 clone해도 됩니다. 빌드의 필수 입력은 저장소 안에 있으며 임시 업로드 경로를 찾지 않습니다.

- `build_bank.py`: 기존 문항에서 중복·변형 → `classify_parts.py` → `build_app_data.py`
- `build_bank.py --reextract`: PDF 추출·이미지부터 위 단계 전체
- `test_bank.py`: 중복·출처·답안 관련 검사
- `test_parts.py`: 분류 상속·검토 목록·내용 기반 회귀 등 검사
- `test_concepts.py`: 개념 노트 구조·파트 연결·출처/상태 일관성·예시 검산·연도별 수치·번들 포함 검사
- `test_app.py`: 실제 UI로 풀이·오답·이어 풀기·복수 정답·백업·모바일·개념 노트 연결 검증
- `test_browser.py`: `review.html`의 필터·중복 비교 등 검증
- `test_explanations.py`: 등록 해설 전체의 연결·보기·검산·출처 상태·세법 시행일, 초기 30개와 초기 출처 해시 보존, 등록/보류/미처리의 완전한 분할, 잘못된 연결 차단 회귀 검사
- `test_explanations_app.py`: 등록 해설 전체를 실제 렌더러로 열고 네 보기·풀이 단계·기록 불변 확인. 초기 30개와 신규 파트별 개념/계산 표본의 실제 채점 흐름, 오답·개념·모바일·준비 중·해설 세트 검증
- 브라우저 테스트 주소: `APP_BASE_URL`, 기본 `http://127.0.0.1:8000/jaegyeong/`
- `package_app.py`: `dist/`에 실행용 및 전체 작업 ZIP 생성; CRC와 포함된 이미지/PDF 확인

`reports/`는 검토 문서와 보존한 확인 자료입니다. 새 테스트 이미지·백업 임시 파일은 `_artifacts/`에 생성하며 커밋하지 않습니다. 일부 과거 보고서는 작성 당시의 단계 설명이므로 현재 집계와 이 문서를 함께 확인하세요.

## 배포와 알려진 환경 제약

사용자는 작업 결과를 `main`에 바로 반영하는 방식을 선택했습니다(PR 없이). 작업 브랜치에도 같은 커밋을 올려 두었습니다. 기존 GitHub Pages 설정은 `main`을 반영하는 `pages build and deployment`입니다. 별도 npm 빌드나 새 Actions 워크플로가 필요하지 않습니다. `main` 업데이트 후 해당 커밋의 Pages 실행이 성공했는지 확인합니다.

7차 당시 7개 테스트 스위트를 실행했습니다. 데이터·원문·기존 해설·출처·노트 보존 및 해설 4,145개 렌더링, 실제 채점·학습 기록 흐름을 검사한 결과는 [7차 당시 검증 기록](reports/round7-validation.json)을 확인하세요. 이전 6차의 38개 회귀·4,090개 렌더링 수치는 과거 검증 기록입니다. 배포는 새 main 커밋의 GitHub Pages 실행과 정상 HTTPS 공개 파일 SHA-256 대조로 확인하며, 로컬 브라우저 검사를 공개 HTTPS 브라우저 검사로 표현하지 않습니다.

과거에는 일부 공식 사이트·GitHub API·공개 서비스 주소 접근이 제한되었으나 이 기록은 당시 환경 설명입니다. 현재 확인 범위는 위 최종 환경 기록을 사용하세요. 웹폰트 CDN을 이용하지 못할 때는 기존 시스템 글꼴 대체가 유지됩니다.

이전 3차부터 마무리까지 실제 사용한 서로 다른 하위 에이전트는 9개(기본 작성자 6개, 재무·원가 마무리 2개, 독립 QA 1개)이며 최대 동시 작업자는 6개였습니다. 메인까지 포함한 동시 슬롯은 7개이고 재귀 에이전트 생성은 없었습니다.

이전 7차 마무리 당시 등록 해설은 4,145개였으며 그때 추가 확인에서 55개를 순증했습니다. 직전 미해결 231개 전부를 실제 하위 에이전트 6개가 11개 독점 배치로 다시 확인했고 새 공식 원본문 확보 후 62개를 3개 별도 배치로 추가 검토했습니다. 새 후보 57개 전체를 작성자와 다른 에이전트가 독립 검수하여 7차 당시 검토 필요는 176개였습니다. 기존 4,090개 해설 전체 객체·순서·출처, 원문·공식 답안·문항 ID·세법 연도와 학습 기록 형식은 보존했습니다. 개념 노트는 74개·기존 확인 상태를 유지하고 M03의 확인된 원리·예제만 덧붙였습니다. 자세한 결과는 [7차 당시 추가 확인 결과](reports/round7-review.md)를 확인하세요. 이전 6차의 187개 추가·231개 보류와 3차 수치는 역사 기록입니다.

3차 시작 시 등록되어 있던 2,854개 해설의 본문과 계산은 보존했습니다. 초기 재무 10개는 필요한 출처·검토 상태 등 특정 메타데이터만 실제 자료와 추가 대조했으며 본문이나 계산을 재생성하지 않았습니다. 문항 ID·공식 정답·원문의 세법 적용 연도와 `chagok.study.v1` 저장 형식은 바꾸지 않았습니다.

74개 파트에 노트가 있으며 `source_checked` 66개, `partial` 8개입니다. 기존 52개에 재무 22개를 추가했고, F01의 추가 핵심 문단은 한국회계기준원 공식 공개 한국어 개념체계와 직접 대조했습니다. 원가 M03·M04·M05·M06·M08·M15·M18·M19의 8개 파트는 확인한 부분만 보강했고 미확인 특수규정은 분리해 `partial`을 유지합니다. 이는 개념체계·기준서·원가 교재의 전체 범위를 모두 검증했다는 뜻이 아닙니다.

공식 공개 목록에서 로그인·개인정보 등록 없이 받을 수 있는 기준서·개념체계 PDF, 실제 읽은 공개 교재 및 역사 법령 보존본을 확인 범위에 맞춰 기록했습니다. 공식 자료의 원문 PDF나 긴 저작권 본문은 저장소에 재배포하지 않습니다. 공개 Git 미러의 고정 커밋·판본·실제 읽은 위치와 원 발행자 대조 한계도 보존합니다. 세법 연도를 시험 연도로 추정하지 않고, 실제 시행일·부칙과 원문 연도를 대조합니다. 답안 의문·원문 누락·필수 규정 미확인은 해소되지 않은 상태로 보류합니다.
