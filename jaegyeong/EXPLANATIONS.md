## 2026-10-13 10차 추가 검토

신규 4개·기존 394개 수정(본문 9개 포함)의 보호 기록은 `round10_followups`입니다. 기존 before 객체·전후 해시·변경 필드·근거·다른 작성자의 독립 QA를 저장하며 정답·보기번호·is_answer·기존 계산식을 바꾸지 않습니다. 신규 등록은 네 보기 모두 검수 통과, `source_checked`, 미확인 항목0개이며 계산식은 숫자와 + − × ÷ 및 괄호만 허용합니다.

[현재 보고서](reports/round10-review.md)·[실제 출처 읽기](reports/round10-source-acquisition.json)·[독립 QA](reports/round10-quality-review.json)가 기준입니다.

## 작성·검토 범위

모두 AI 작성 학습용 해설입니다. 삼일회계법인의 공식 해설이 아니며 전문가 검수는 아직 받지 않았습니다. 초기 30개의 원문 확인 결과를 유지하고, 추가분은 담당자가 원문 PDF·보기·표/그래프와 대조했습니다. 등록 해설 전체의 공식 답안 배열·문항 해시·보기별 정답 표시를 자동 대조합니다. 수치 계산은 안전한 산술 평가기로 자동 검산합니다.

다음 표는 **초기 30개 작성 당시**의 검토 상태를 보존한 역사 기록입니다. 이후 초기 재무 10개는 필요한 출처·검토 상태 등 특정 메타데이터만 실제 자료와 추가 대조했고 본문·계산은 보존했습니다. 현재 상태·집계·개별 보류 사유는 [현재 해설 감사 기록](reports/explanation-expansion.json)과 [미해결 재검토 결과](reports/미해결재검토결과.md)를 확인하세요.

초기 해설 작성 당시에는 한국회계기준원 직접 접근이 403으로 제한되어 기존 개념 노트와 미확인 표시를 사용했습니다. 이후 3차에서는 실제 읽은 영문 원문·공개 교재와 접근 가능한 공식 공개 PDF를 추가 확인했고, 출처마다 직접 읽은 판본·문단과 검증 한계를 기록했습니다. 초기 재무 10개의 특정 검토 메타데이터 보완과 신규 해설 작성은 별개의 작업입니다. 한국어 원문 일부를 확보했다는 이유로 미확인 전체 기준·특수조건을 확인했다고 표시하지 않습니다.

세법은 `legalize-kr/legalize-kr`의 국가법령정보센터 OpenAPI 보존 자료를 사용했습니다. 각 출처에 실제 읽은 커밋·시행일·공포번호·파일 링크를 남겼습니다. 앞으로 시행될 법령 판본을 현재 연도에 적용하지 않습니다. 소득세법 제17조의 11% 배당가산 개정은 법률 제21221호 부칙 제14조의 경과규정을 함께 확인했습니다. 수록 문제의 10% 가정 및 적용 연도를 따릅니다. 직접 대조한 법령 판본은 `data/explanations.json`의 `sources`가 기준입니다.

원가는 `openstax/osbooks-principles-accounting-bundle`의 실제 읽은 커밋을 출처 링크에 고정했습니다. 공개 교재의 라이선스는 CC BY-NC-SA 4.0이며, 원문 설명·예제를 옮겨 싣지 않고 해당 기출 조건으로 풀이를 작성했습니다. 원문 PDF나 외부 교재 파일을 저장소에 추가하지 않았습니다.

## 원본과 생성 절차

`data/explanations.json`이 편집 원본입니다. `schema_version: 1`이며 `sources`에 실제 대조 자료의 정보, `items`에 해설을 저장합니다. 주요 필드는 다음과 같습니다.

- `question_id`: 기존 `entries.json`의 문항 ID. 출제 이력·유형 그룹으로 자동 상속하지 않습니다.
- `question_fingerprint`: ID·본문·보기·공식 답안·적용 세법 연도의 SHA-256입니다. 정규화 없이 원문 데이터를 기준으로 합니다.
- `answers`, `tax_law_year`, `part_id`: 공식 답안·원문 연도·관련 개념 연결입니다.
- `summary`, `steps`, `option_notes`: 해설 결론, 단계별 풀이, 네 보기의 설명입니다. `is_answer`는 시험에서 선택해야 하는 보기인지 뜻하며, 문장 자체가 옳다는 뜻이 아닙니다.
- `checks`: 검산식과 예상 결과입니다. 가격차이 등은 양수 불리/음수 유리, 증분손익은 양수 증가/음수 감소로 작성합니다.
- `sources`, `review_status`, `review_note`, `unchecked_points`, `authorship`, `checked_on`: 출처·검토 범위·미확인 내용·작성 구분·확인일입니다.

`scripts/explanation_data.py`가 연결을 검증하고 `build_app_data.py`가 생성 번들의 `explanations`에 포함합니다. 원문이나 답안을 바꾸면 재검토 없이 이전 해설을 배포하지 못하도록 빌드가 실패합니다. 이를 해제하려고 해시만 덮어쓰지 마세요. 원문 이미지·확정답안·적용 연도·계산을 확인하고 해설과 검토 기록을 함께 수정한 뒤 `question_fingerprint(q)`로 해시를 갱신하세요.

```sh
python jaegyeong/scripts/build_app_data.py
python jaegyeong/scripts/test_bank.py
python jaegyeong/scripts/test_parts.py
python jaegyeong/scripts/test_concepts.py
python jaegyeong/scripts/test_explanations.py
# 저장소 루트를 HTTP로 제공한 뒤 실행
python jaegyeong/scripts/test_app.py
python jaegyeong/scripts/test_browser.py
python jaegyeong/scripts/test_explanations_app.py
```

루트 사이트, 기존 문항 데이터·ID·정답, `chagok.study.v1` 저장 형식은 이 기능에서 변경하지 않았습니다. 해설 열람 자체는 시도 횟수·오답 상태·세션 위치를 바꾸지 않습니다. 해설 세트 풀이의 채점은 기존과 동일하게 기록합니다.

## 추가 해설의 출처·동시 작업·통합

원본 질문·정답·문항 ID·파트·적용 세법 연도·학습 기록 형식을 유지합니다. 실제 읽은 공개 교재(OpenStax·Saylor)의 관련 본문/수식/도표 및 적용 당시 법령 Git 보존본을 인용합니다. 추가 자료가 있는 경우 각 `sources`의 고정 커밋·버전·직접 확인 범위가 기준입니다. K-IFRS 고유 규정은 일반 미국 교재의 규칙과 같다고 추정하지 않습니다. 문제에서 방법·인식금액을 명시한 경우 그 조건의 산술만 검증할 수 있습니다. 세법은 시험월과 원문 적용 연도의 범위, 시행일·부칙을 대조하고 `null`을 시험 연도로 덮어쓰지 않습니다.

각 작업자는 독점 배치의 임시 출력만 쓰고 메인만 원본 JSON을 수정합니다. 신규 출력은 아래 형식이며 모든 배정 ID를 `items` 또는 `review`에 정확히 한 번 기록합니다.

```text
BATCH.input.json: {batch_id, questions: [원본 questions.json 행 20~30개], examples: [기존 형식 예]}
BATCH.output.json: {schema_version: 1, batch_id, sources, items, review, validation}
review 행: {question_id, reason, category}
category: source_unverified | answer_suspected | parse_problem | calculation_unresolved
approved-batches.json: 메인이 검토한 batch_id 배열
approved-batch-hashes.json: 승인 시 출력 SHA-256 (동시 수정 감지용)
```

```sh
python jaegyeong/scripts/merge_explanation_batches.py /absolute/batch-directory
python jaegyeong/scripts/build_app_data.py
```

통합기는 ID·배정 중복·누락·기존 해설 덮어쓰기·답안·연도·출처·시행일·모든 검산식을 검사한 후 기록합니다. 이미 통합된 배치는 다시 추가하지 않습니다. 보류 문항을 나중에 해소하는 경우는 해당 문항만 재대조하고 감사 JSON의 분할/집계 및 `review_resolutions`까지 갱신하는 별도 교정 작업입니다. 기존 완성 문항의 계산/문장 재생성으로 취급하지 않습니다. 생성 번들을 직접 수정하지 마세요.

보류의 `answer_suspected`는 공식 답안이 틀렸다고 확정한 표시가 아닙니다. 휴일 특례·누락 조건·표 수치 모순·문언 범위 등을 추가 확인할 대상이며, 공식 답안은 그대로 보존합니다. 이번 등록 해설의 전문적 정확성은 별도 전문가 검수가 필요합니다.

## 과거 기록: 1·2차 재검토와 개념 노트 확장

1차 보류 1,673개 전부를 실제 6개 작업자에게 20~30개씩 균등 재배정하여 추가 자료·원문과 대조했습니다. 2차 완료 당시 206개를 해소해 등록했고 1,467개를 갱신한 검토 사유와 함께 남겼습니다. 이 1,467개가 이번 3차의 입력이며 현재 보류 수는 아닙니다. 감사 JSON의 `rechecks`는 1차 보류 사유와 2차 배정·결과·출력 해시를 보존하고, `review_resolutions`는 해소 근거를 기록합니다. 이미 등록된 해설은 재작성하지 않았습니다. `scripts/merge_explanation_rechecks.py`는 승인된 재검토 출력만 추가하며 기존 해설·출처를 보호합니다.

2차 완료 당시 개념 노트 37개를 추가하여 52개였습니다. 기존 15개와 출처 내용은 해시로 보존하고, 새 노트에는 핵심 원리·공식·풀이팁·검산 예시·직접 대조한 판본을 기록했습니다. 제한된 확인 범위와 미확인 특수규정은 따로 표시합니다. K-IFRS 원문을 새로 확인하지 못한 파트는 추정하여 추가하지 않았습니다. 새 세무 노트가 인용하는 국세기본법·소득세법 시행령 등 추가 법령은 새 출처키와 실제 판본을 사용합니다. 기존 데이터 구조와 UI·저장 형식은 유지합니다.

## 2차 재검토 입력과 승인

```text
RECHECK.input.json: {batch_id, questions: [원본 행 20~30개], previous_review: [배정 당시 보류 행], examples}
RECHECK.output.json: {schema_version: 1, batch_id, sources, items, review, validation}
approved-rechecks.json: 메인이 검토한 recheck batch_id 배열
approved-recheck-hashes.json: 승인한 출력 SHA-256
```

```sh
python jaegyeong/scripts/merge_explanation_rechecks.py /absolute/batch-directory
python jaegyeong/scripts/build_app_data.py
```

이 통합기는 기존 보류 사유와 입력 스냅샷이 같은지 확인하며, 이미 이 2차에서 배정된 ID의 재배정을 거부합니다. 이번 3차는 별도 배정·출력 해시·검토 및 해소 이력을 감사 기록에 남겼습니다. 이후 재검토도 해당 문항의 분할·집계·해소 이력을 함께 갱신해야 합니다. 승인 후 결과가 바뀌면 자동 재통합되지 않습니다. 필요한 필드만 검증하여 교정하고 이전/새 출력 해시와 이유를 `submission_amendments`에 남깁니다.

당시 최종 추가 QA에서는 2차 등록분 205개를 별도 작업자가 읽기 검토했습니다. 요약 대상 금액 1건, 출처 제목 1건과 인용 위치 1건을 메인이 실제 지문·교재·독립 계산과 다시 대조하여 교정했습니다. 상세 ID와 전후 해시는 감사 기록의 `final_quality_review`에 있습니다. 기존 30개 해설·기존 출처는 이 교정에서도 보존했습니다.

## 과거 기록: 3~7차 재검토 상태

이전 3차부터 마무리까지 실제 사용한 서로 다른 하위 에이전트는 9개(기본 작성자 6개, 재무·원가 마무리 2개, 독립 QA 1개)이며 최대 동시 작업자는 6개였습니다. 메인까지 포함한 동시 슬롯은 7개이고 재귀 에이전트 생성은 없었습니다.

7차 마무리 당시 등록 해설은 4,145개였으며 그때 추가 확인에서 55개를 순증했습니다. 직전 미해결 231개 전부를 실제 하위 에이전트 6개가 11개 독점 배치로 다시 확인했고 새 공식 원본문 확보 후 62개를 3개 별도 배치로 추가 검토했습니다. 새 후보 57개 전체를 작성자와 다른 에이전트가 독립 검수하여 7차 당시 검토 필요는 176개였습니다. 기존 4,090개 해설 전체 객체·순서·출처, 원문·공식 답안·문항 ID·세법 연도와 학습 기록 형식은 보존했습니다. 개념 노트는 74개·기존 확인 상태를 유지하고 M03의 확인된 원리·예제만 덧붙였습니다. 자세한 결과는 [7차 당시 추가 확인 결과](reports/round7-review.md)를 확인하세요. 이전 6차의 187개 추가·231개 보류와 3차 수치는 역사 기록입니다.

3차 시작 시 등록되어 있던 2,854개 해설의 본문과 계산은 보존했습니다. 초기 재무 10개는 필요한 출처·검토 상태 등 특정 메타데이터만 실제 자료와 추가 대조했으며 본문이나 계산을 재생성하지 않았습니다. 문항 ID·공식 정답·원문의 세법 적용 연도와 `chagok.study.v1` 저장 형식은 바꾸지 않았습니다.

74개 파트에 노트가 있으며 `source_checked` 66개, `partial` 8개입니다. 기존 52개에 재무 22개를 추가했고, F01의 추가 핵심 문단은 한국회계기준원 공식 공개 한국어 개념체계와 직접 대조했습니다. 원가 M03·M04·M05·M06·M08·M15·M18·M19의 8개 파트는 확인한 부분만 보강했고 미확인 특수규정은 분리해 `partial`을 유지합니다. 이는 개념체계·기준서·원가 교재의 전체 범위를 모두 검증했다는 뜻이 아닙니다.

공식 공개 목록에서 로그인·개인정보 등록 없이 받을 수 있는 기준서·개념체계 PDF, 실제 읽은 공개 교재 및 역사 법령 보존본을 확인 범위에 맞춰 기록했습니다. 공식 자료의 원문 PDF나 긴 저작권 본문은 저장소에 재배포하지 않습니다. 공개 Git 미러의 고정 커밋·판본·실제 읽은 위치와 원 발행자 대조 한계도 보존합니다. 세법 연도를 시험 연도로 추정하지 않고, 실제 시행일·부칙과 원문 연도를 대조합니다. 답안 의문·원문 누락·필수 규정 미확인은 해소되지 않은 상태로 보류합니다.

## 3차 이후 재검토·교정의 재현

완성 해설은 다시 생성하지 않습니다. `reports/explanation-expansion.json`의 현재 `review`에서 독점 배정하고 입력에 정확한 기존 검토 행을 보존합니다. 최신 보류를 다시 배정하는 경우 `extra_round`를 이전보다 높게 지정합니다. 같은 라운드 안에서는 ID가 중복될 수 없고, 다음 라운드도 현재 보류인 문항만 허용합니다. 과거 배정·보류 사유·출력 해시는 지우지 않습니다.

```text
BATCH.input.json: {batch_id, extra_round: 6, worker, questions: [원본 행 20~30개], previous_review: [배정 직전의 해당 review 행]}
BATCH.output.json: {schema_version: 1, batch_id, sources, items, review, validation}
approved-followups.json: 메인이 실제 검토한 batch_id 배열
approved-followup-hashes.json: 승인 시 출력 SHA-256 맵
```

```sh
python jaegyeong/scripts/merge_explanation_extra_rechecks.py /absolute/batch-directory
python jaegyeong/scripts/build_app_data.py
# README의 7개 테스트 스위트를 실행
```

3차 첫 전체 재검토는 `merge_explanation_followups.py`가 `manifest.json`과 승인 출력 해시를 대조하여 통합했습니다. 재실행은 이미 기록된 배치를 건너뜁니다. 문장만의 승인 교정은 `apply_explanation_amendments.py`, 검증된 개념의 덧붙이기는 `merge_concept_followups.py`, 새 해설에서 필수 조건이 부족함을 발견한 경우는 `quarantine_new_explanation.py`를 사용합니다. 각 교정은 기존·변경 후 해시와 확인 근거를 감사 기록에 남기며 초기 2,854개 해설의 본문·계산을 보호합니다. 초기 재무 10개의 이미 검증된 메타데이터 승격은 별도 기록되어 있습니다.

현재 남은 검토 목록은 [CSV](reports/해설추가검토목록.csv)에서도 읽을 수 있습니다. 이 목록의 답안은 공식 답안 그대로이며 `answer_suspected`는 답안 오류 확정이 아닙니다.
