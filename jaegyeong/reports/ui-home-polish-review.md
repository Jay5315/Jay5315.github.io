## 실제 브라우저 검사

새 `test_home_polish.py`는 기존 `test_robustness.py`에서 실행합니다. 360/390/640/641/1280px, 밝음/어두움, 보통/아주큰글자10조합을 확인했습니다. 모든조합에서 홈 두 문구의 천단위 쉼표를 확인했고, 휴대폰에서는 두 버튼이 가로/세로44px 이상입니다. 글자 위쪽 바깥의 확장된 영역을 실제 hit-test하고 클릭해 파트 선택이 해제되고 백업·복원 창이 열리는 것을 확인했습니다. 데스크톱에서는 원래 높이를 유지하며 가로 넘침과 JavaScript오류도 없습니다.

주 담당자가 전후 측정값을 대조한 결과, 모바일 버튼높이는22.390625→44.390625px, 데스크톱은22.390625px입니다. 열조합 모두 글자영역의 가로/세로치수·fontSize14px·fontWeight700·lineHeight·글자색·투명배경·테두리가 같습니다. 최종360px 밝음/어두움 캡처를 직접 읽어 숫자 표시와 두 버튼을 확인했습니다. 물리적 휴대폰과 실제 화면낭독기 음성 검사는 아닙니다.

## 수정 전 실제 실패

수정 전 숫자검사는 실제 `해설 4281문항 풀기` 때문에 실패했고, 누르는 영역 검사는360px 버튼높이22.390625px 때문에 별도로 실패했습니다. 수정 후 두 조건을 포함한 열조합 검사가 통과했습니다. 대기 시간은 늘리지 않았습니다.

첫 측정 보조 명령은 Git객체 경로에 `jaegyeong/../index.html`을 그대로 넘겨 종료했습니다. 경로를 저장소 기준으로 정규화한 뒤 보호 파일 바이트 검사를 통과했습니다. 이것은 앱/브라우저 검사 실패가 아니며 소스·데이터를 바꾸지 않았습니다.

## 기존 UI 보호 정책 적용 누락 보완

정상 UI 변경을 기록한 직후30차 전용 검사1개가 기존 `assets/app.js` 원시 해시와 다르다며 실패했습니다. 최근27~30차 데이터 검사 일부가 오래전21~24차 검사에서 이미 사용하던 `reports/ui-changes.json` 체인을 적용하지 않고 원시 해시만 비교하고 있었습니다.

기존 `assert_protected_file`의 정책을 `log_ui_change.py`의 공통 `expected_ui_hash`로 옮겨 같은 기준으로 확인하게 했습니다. **기존 감사 원장·제안의 기대 해시는 단 하나도 바꾸지 않았습니다.** UI두파일만 연속 감사체인을 따라가고 실제 파일의 SHA-256과 비교하며, 다른 파일은 원래 원시 해시와 계속 일치해야 합니다. 기존 HTML 진입점 복원과 모든 나머지 단언도 유지합니다.

이 공통 검증은 예전 정책에 체인 연결·해시형식·기록 범위의 엄격한 검사를 더합니다. 기존 체인종료 검사도 그대로 남겼고, 새 `test_ui_change_chain.py`의2개 검사는 실제 모든 과거 UI버전이 현재 파일에 닿는지, 기록 누락·단절·비정상 해시·다른 파일 허용 시도를 거부하는지 확인합니다. 보완 후30차전용2개·전체해설79개가 통과했습니다.
