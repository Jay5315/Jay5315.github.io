## 2. 권장 저장 단위: 최상위 값 하나당 파일 하나

처음에는 최상위 키 95개를 각각 하나의 JSON 값 파일로 저장합니다. 작은 스칼라도 별도 파일로 두어 분할·합치기 규칙을 단순하게 유지합니다. 파일 수를 줄이기 위해 여러 회차를 임의로 합치지 않습니다.

제안 경로:

```text
reports/explanation-ledger/
  manifest.json
  parts/
    0000-schema_version-<내용해시>.json
    ...
    0091-round27_sources-<내용해시>.json
    0092-round28_followups-<내용해시>.json
    0093-round29_followups-<내용해시>.json
    0094-round30_followups-<내용해시>.json
```

경로 순번은 기준 원장의 실제 최상위 삽입 순서입니다. 예시의 마지막 4개는 현재 순서와 같습니다. 파일명만 보고 적용·되돌리기 순서를 정하지 않습니다. 각 파일에는 해당 값 자체만 저장하고, 기존 객체 안에 분할 메타데이터를 넣지 않습니다. 기존 원장의 `schema_version` 값도 바꾸지 않습니다.

실제 큰 값의 독립 직렬화 크기(들여쓰기 2, 마지막 LF 포함):

| 최상위 키 | 바이트 |
|---|---:|
| `round10_followups` | 13,718,763 |
| `round20_followups` | 3,937,465 |
| `round26_followups` | 3,693,627 |
| `third_pass_batches` | 3,403,683 |
| `spacing_round3` | 2,937,419 |

현재 가장 큰 값도 약 13.08MiB입니다. 제안 운영 기준은 파일 20MiB에서 경고, 32MiB가 되기 전에 추가 분할 설계입니다. 향후 한 회차가 이를 넘으면 그때 배열 순번 범위를 나누는 별도 승인안을 작성합니다. 이번에 중첩 객체를 재귀적으로 분할하거나 내용의 중복 제거를 하지 않습니다. `before/after`, `original_review`, 판정 과거 기록, 기존 출처 정의와 해시는 반복되어 있어도 모두 보존합니다.

## 3. 매니페스트와 기존 논리 객체의 경계

새 매니페스트에는 다음 정보만 둡니다.

- 저장 포맷 버전(원장 `schema_version`과 별개), 마이그레이션 기준 전체 커밋 ID·기존 경로·원시 SHA-256·논리 SHA-256.
- 고정 직렬화 규칙과 최상위 키 전체의 순서. 매 항목의 키·순번·값 타입·상대 경로·바이트 수·파일 SHA-256·값의 기존 방식 논리 해시.
- 해당 시점 전체 논리 객체의 현재 해시와 호환 직렬화 해시. 이후 정상 감사 단계가 추가되면 현재 해시는 달라지지만, 마이그레이션 시작점과 과거의 보호 해시는 그대로 남깁니다.

로더는 매니페스트의 파일 해시와 타입·키·순서·개수를 검증하고, 원래와 같은 새 Python `dict`를 완성해 반환합니다. `manifest`, 경로, 크기, 저장 포맷 버전 등을 반환하는 논리 원장 안에 섞지 않습니다. 그래야 `digest(old_audit)`가 과거와 같은 입력을 받습니다.

중복 키·순번·경로, 누락 부품, JSON 파싱 오류, 예상 타입 불일치, 해시 불일치, 미등록 부품을 조합에 끼워 넣으려는 요청은 오류로 중단합니다. 상대 경로의 `..`·절대 경로·외부 URL·저장소 밖 심볼릭 링크도 거부합니다. 해시만 새로 적으면 임의 내용이 승인되는 구조가 되어서는 안 되므로, 마이그레이션 기준 해시는 승인된 커밋과 별도 고정 회귀 검사에도 결속합니다. 이후 내용 변경은 기존 회차별 감사·독립 검수 절차를 그대로 통과해야 합니다.

## 5. 분할 전후 동일성의 증명

승인된 구현은 아래 네 수준을 모두 통과해야 합니다.

1. **원본 파일 증명:** 기준 커밋의 `git show <전체커밋>:jaegyeong/reports/explanation-expansion.json` 바이트와 SHA-256을 고정합니다. 현재 문서의 기준 해시는 1절과 같습니다. 구현할 때 main이 바뀌었다면 새 실제 기준을 별도로 기록하며 이번 기준을 소급 수정하지 않습니다.
2. **논리 내용 증명:** 전체 객체의 키·타입·값, 배열 순서와 길이, 모든 최상위 값의 해시, 전체 기존 `digest`가 같아야 합니다. 문자열의 유니코드 정규화·공백 정리·숫자 형변환·배열 정렬은 금지합니다. 예를 들어 Python의 단순 `True == 1`만으로 동등하다고 판정하지 않고 직렬화 해시와 타입 비교도 확인합니다.
3. **원시 바이트 복원 증명:** 삽입 순서를 포함한 복원 객체를 UTF-8, `ensure_ascii=False`, `indent=2`, `sort_keys=False`, 마지막 LF 1개로 내보내면 원본과 바이트 단위로 같아야 합니다. 현재 원본은 이 왕복이 실제로 성립합니다. 각 부품의 실제 서식이 원본 전체의 들여쓰기와 달라도, 검증된 호환 내보내기의 SHA-256은 원본과 같아야 합니다. 미래 원장에 이 규칙이 성립하지 않으면 자동 전환을 중단하고 별도 보존 설계부터 검토합니다.
4. **과거 단계 증명:** 기존 단일 파일에서 실행한 복원 순서와 분할 로더에서 실행한 같은 순서의 단계별 `data/audit` 논리 해시를 대조합니다. 기존 `baseline_audit_hash`, `baseline_data_hash`, `baseline_source_hashes`, 항목 `before/after_hash`가 모두 그대로 통과해야 합니다. 기존에 원시 해시를 기록한 단계는 그 단계에서 검증하던 동일 바이트를 계속 입력으로 사용합니다. 현재 원본의 해시를 모든 과거 단계의 원시 해시로 취급하지 않습니다.

분할했다고 새로운 해설 수정 감사 단계를 원래 객체 안에 추가하면 전체 감사 해시가 바뀝니다. 따라서 저장 매체 변경 증거는 별도 마이그레이션 보고서에 두며, 해설·기존 감사 객체를 동시에 수정하지 않습니다. 증명서는 기준 커밋, 원본/복원 바이트 해시, 전체/각 값 논리 해시, 키 순서, 단계별 대조 결과, 시험한 명령과 결과를 포함해야 합니다.

## 6. 기존 검사를 유지한 검증 계획

다음은 승인 후 실행할 완료 조건입니다. 이번 문서 작성만으로 분할 검사를 통과했다고 보고하지 않습니다.

- 기존 필수 7개와 `test_offline.py`를 순차 실행해 통과. 해설 검사 74개를 삭제·skip·완화하지 않음. 분할 시점에 새 검사가 추가되어 있다면 그 검사도 포함.
- 새 전용 검사로 원본/복원 바이트 동일성, 95개 키 완전성·순서·타입·값, 단계별 복원 결과 동등성, 과거 해시 보존 확인.
- 한 부품 변조, 부품 누락, 매니페스트 키/순번 중복, 원래 배열 재정렬, 숫자/불리언 치환, 잘못된 경로, 최신·구버전 혼합 시 각각 거부하는 음성 검사.
- 파일을 쓰다 중단되는 경우, 잘못된 기존 세대를 기대값으로 사용한 쓰기, 동시 작성 충돌을 거부하는 검사. 실패한 저장이 기존 매니페스트를 손상시키지 않아야 함.
- 동일 데이터를 양쪽 저장소에서 읽어 `build_app_data.py`로 생성한 번들·매니페스트·과목 청크가 바이트 단위로 같음. 비교는 별도 임시 작업 디렉터리에서 수행.
- ZIP 2종과 `test_portable_runtime.py` 실행. 전체 ZIP에는 매니페스트·부품·읽기 도구가 빠짐없이 들어가고, 임시 새 폴더에 압축을 푼 뒤 원장 로드·기존 보호 검사를 수행. 실행용 ZIP의 앱 자산은 불변.
- 앱 배포물이 달라지지 않았어도 요청된 배포가 있다면 해당 커밋의 Pages 성공과 공개 파일 13개 SHA-256 대조를 기록.

과거 보호 해시를 새 값으로 갱신해 검사를 맞추거나, 부품만 검증하고 원장 전체·복원 검사를 빼는 방식은 허용하지 않습니다. 새 음성 검사의 실패 전 재현은 승인된 구현 때 기록합니다. 이번은 문서 작업이므로 수정 전 앱 실패를 만들 이유가 없습니다.

## 7. 쓰기·전환·되돌림 절차

사용자 승인 뒤에는 다음을 분리해서 검토 가능한 변경으로 진행합니다.

1. 새 기준 main을 확정하고 기존 원장 바이트·키·단계별 해시·실제 검사 결과를 고정. 동시 감사 변경을 멈추고 데이터 변경 없는 이관만 수행.
2. 임시 위치에 부품과 매니페스트 작성. 기존 원장과 동등성을 전부 검사한 뒤 읽기 계층·소비자 전환을 함께 검토. 기존 검사 함수·기대값은 보존.
3. 새 저장은 내용 해시 파일명으로 부품을 먼저 기록하고 각 파일을 검증한 뒤 마지막에 매니페스트를 같은 파일 시스템에서 원자적으로 교체. 이전 매니페스트 해시를 쓰기 선행 조건으로 비교하고 잠금으로 동시 작성 차단. 독자는 이미 읽은 매니페스트가 가리키는 불변 파일만 사용. 중단 시 기존 매니페스트가 계속 유효해야 함. Git 반영은 모든 관련 파일을 한 커밋으로 묶음.
4. 이미 커밋한 과거 부품은 덮어쓰지 않음. 참조되지 않는 부품 정리는 별도 정책/승인으로 다루고 마이그레이션 과정에서 임의 삭제하지 않음. 이후 정상 감사 작성은 기존 논리 절차를 거쳐 변경된 값 파일과 새 매니페스트만 반영.
5. 전체 검사·동일성 증명·새 폴더 ZIP 검증을 마친 뒤 기존 추적 단일 파일 제거. 사용자/Claude 검수용 원본 호환 내보내기는 `dist/` 또는 임시 폴더에만 보관. 거대한 원본 복사본을 다시 커밋하지 않음.
6. 실패하면 전환 커밋을 되돌려 마지막 정상 커밋의 저장 구조와 소비자를 함께 복원. 이후 감사가 추가된 상태라면 단순히 옛 원본으로 덮어쓰지 않고, 현재 분할 원장을 검증해 호환 단일 파일로 내보내는 역이관을 별도 승인받음. 어느 경우에도 강제 푸시·이력 삭제·보호 해시 재설정은 하지 않음.

## 8. 이번 범위의 결과와 남은 결정

이번에는 원장 읽기·크기/해시/중복 키/현재 직렬화 왕복 확인과 설계 문서 작성만 했습니다. 부품 생성·이관 코드·공통 로더·기존 소비자·기존 검사는 수정하지 않았습니다. 미래 분할 후의 성능, 실패 중단 안전성, 전체 ZIP 복원은 구현 전이므로 미검증입니다.

권장안은 **최상위 값별 분할 + 엄격한 매니페스트 + 원래 객체를 돌려주는 공통 계층 + 원시 바이트 내보내기 증명**입니다. 57MB인 현재 원장을 즉시 바꿔야 하는 것은 아니며, 이 설계의 실제 구현은 사용자 승인 뒤 별도 작업으로 진행합니다.
