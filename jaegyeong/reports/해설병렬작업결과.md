## 작업과 보존

미작성 4,291개를 20~30개씩 152개 독립 배치로 분배했습니다. 메인이 기존 결과와 배정 ID를 확인하고 원본 JSON에 통합했습니다. 1차 보류 1,673개도 20~30개씩 57개 배치로 다시 분배하여 추가 교재·법령·원문과 대조했습니다. 새 근거로 해소할 수 있는 항목만 등록했고, 해결되지 않은 사유를 갱신했습니다. 실제 사용 가능한 동시 슬롯은 메인 포함 7개였으므로 하위 작업자는 최대 6개입니다. 하위 에이전트의 재귀 생성은 없었습니다.

각 작업자는 서로 다른 임시 출력만 작성했습니다. 메인이 배정·공식 답안·원문 해시·적용 연도·법령 시행일·모든 산술식을 검증하고 출력 변경 감지용 SHA-256과 완료 기록을 확인한 후 승인했습니다. 같은 원본 파일을 여러 에이전트가 동시에 쓰지 않았습니다. 기존 30개와 기존 출처, 기존 15개 개념 노트와 출처는 내용 해시로 보존합니다. 새 해설만 문장 종결·숫자 표기·불필요한 내부 필드 용어를 정리했습니다.

## 근거 범위와 보류

OpenStax와 Saylor의 실제 본문·수식·도표 및 law.go.kr 자료의 Git 보존본에서 실제 시행 판본·부칙을 확인했습니다. US GAAP 교재만으로 K-IFRS 고유 규정을 확인했다고 표현하지 않습니다. 추가 접근을 시도한 IFRS·회계기준 사이트는 이 환경에서 차단돼, 직접 확인되지 않은 인식·측정 규칙은 계속 보류했습니다. 세법 연도가 원문에 없는 문항은 연도를 추정하지 않았습니다.

| 최종 보류 범주 | 문항 수 |
|---|---:|
| source_unverified | 1,384 |
| answer_suspected | 41 |

`answer_suspected`는 답안 오류 확정이 아닙니다. 휴일 특례, 표의 수치, 누락 조건, 문언 범위 등을 더 확인할 대상입니다. 공식 답안은 변경하지 않았습니다. 기존 재무 10개 해설의 `partial` 표시도 유지합니다. 최종 등록 보류 수와 기존의 재대조 표시 10개는 별도 집계입니다.

개별 ID·이전 사유·재검토 사유·해소 근거는 [explanation-expansion.json](explanation-expansion.json)의 `review`, `rechecks`, `review_resolutions`에 있습니다. 개념 노트의 배정·등록·보류와 기존 해시 보호는 [concept-expansion.json](concept-expansion.json)에 있습니다.

## 기능과 검증

문항 본문·보기·공식 답안·ID·분류·중복 그룹·학습 기록 `chagok.study.v1`의 구조와 루트 Muse 사이트는 유지했습니다. 신규 데이터는 `build_app_data.py`로만 번들에 반영했습니다. 앱에는 기존 해설 필터·채점 후 풀이·보기별 이유·개념 노트 화면으로 표시합니다.

최종 로컬 검증은 모두 통과했습니다.

| 검사 | 결과 |
|---|---|
| `test_bank` / `test_parts` | 10 / 5건 통과 |
| `test_concepts` / `test_explanations` | 6 / 8건 통과 |
| `test_app` / `test_browser` | 실제 Chromium 기능 검사 통과, 브라우저 오류 없음 |
| `test_explanations_app` | 2,854개 해설 전체 렌더링 및 150개 실제 채점 흐름 통과 |
| 계산 검증 | 해설 3,038식 + 개념 노트 150식 통과 |
| 개념 노트 화면 | 52개 전부 데스크톱·모바일 열람 및 기록 불변 통과 |
| 무결성 | 원문·답안·분류 번들 불변, 초기 해설·노트·출처 해시 불변, 전체 대상 정확히 등록/보류로 분할 |
| 통합 재실행 | 두 통합기 모두 중복 없이 원본·감사 파일 바이트 불변 |

등록 해설의 숨김/채점 후 공개, 오답 노트·재시작·키보드·복수 정답·독립 변형·준비 중·해설 세트·학습 기록 보존을 검사했습니다. 별도 작업자의 2차 등록분 205개 읽기 QA와 메인의 해당 지문/출처/계산 재검토에서 요약 1건·출처 제목 1건·인용 위치 1건을 필요한 필드만 교정했습니다. 최종 수치와 검사 범위는 감사 JSON의 `final_validation`과 `final_quality_review`에 기록했습니다.

브라우저 검사는 로컬 생성 번들 기준입니다. GitHub 저장과 Pages 실행은 푸시한 커밋으로 별도 확인하며, 이 환경에서 차단된 공개 주소의 직접 브라우저 접속을 확인했다고 표현하지 않습니다. 출처 대조는 전문가의 전 문항 검수를 대신하지 않습니다.
